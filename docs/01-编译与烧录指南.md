# 01 · 编译与烧录指南

> 适用：ML307A-DSLN（ASR1606）· 中移 OpenCPU SDK 1.4.2 · Windows
> 本文所有结论均在本机实测得出，关键处标注证据来源。

## 一、环境要求（不需要 Keil）

SDK 是**自包含**的，工具链随包提供：

| 组件 | 位置 | 实测版本 |
|---|---|---|
| ARM 编译器 | `tools/toolchain/gcc-arm-none-eabi/` | `arm-none-eabi-gcc 8.3.1 20190703` |
| make | `tools/utils/make.exe` | GNU make（MinGW 构建） |
| Python | `tools/utils/python3/` | 仅打包脚本使用 |
| 打包工具 | `tools/aboot/arelease.exe` | ASR aboot 打包器 |

**官方流程**：
```
ML307A_build.bat clean
ML307A_build.bat DSLN        ← DSLN 对应 ML307A-DSLN，FLASH_OPT=8M / GNSS_OPT=NO
```
`ML307A_build.bat` 支持 `DCLN / DSLN / GSLN / GCLN` 四个子型号，**各型号底包不同，不可混用**。
路径**不能含中文或空格**（脚本里写死）。

## 二、官方脚本在本机会踩的两个坑（已在本工程绕过）

### 坑 1：SDK 自带 make 找不到 POSIX shell，连 `echo` 都执行不了

现象：
```
process_begin: CreateProcess(NULL, echo "compile ...", ...) failed.
make (e=2): 系统找不到指定的文件。
```
原因：SDK 的 `make.exe` 需要一个 `sh.exe` 来执行 Makefile 里 `@echo 'compile $<'`
这类配方，但 **SDK 里没有带 `sh.exe`**。

两种解法：

- **方案 A（推荐，本工程采用）**：让 make 直接用 `cmd.exe` 当 shell，完全不依赖 MSYS：
  ```powershell
  make -f tools\scripts\Makefile all -j4 -e `
       MODEL_NAME=ML307A MODEL_TARGET=DSLN HW_REVISION=H0 `
       SW_REVISION=202501010000 DEMO_SUPPORT=n SHELL=cmd.exe
  ```
- **方案 B**：把 Git for Windows 的 MSYS shell 挂进 PATH（`D:\Program\Git\usr\bin`）。
  ⚠ 但在受限沙箱/安全策略下 MSYS 会因"无法创建命名管道"而崩溃
  （`couldn't create signal pipe, Win32 error 5`），方案 A 无此问题。

### 坑 2：`pack.bat` 依赖 build.bat 设置的环境变量

单独运行 `tools\scripts\pack.bat` 会得到：
```
文件不存在: \prebuild\baseline\
directory \out\images\ not exist
```
因为它依赖 `PROJECT_ROOT / MODEL_NAME / MODEL_TARGET / FLASH_OPT / GNSS_OPT`。
本工程的 `tools\build_firmware.ps1` 已显式补齐这些变量。

## 三、一键编译（本工程提供）

```powershell
pwsh -File tools/build_firmware.ps1
```
该脚本会依次：
1. 调用 `tools/deploy_to_sdk.ps1` 把 `app/` 源码部署进 `sdk/.../custom/applaction/` 并生成 `custom/custom.mk`
2. 用 `SHELL=cmd.exe` 调 make 编译（`ML307A-DSLN` = `DSLN`，`DEMO_SUPPORT=n`）
3. 调 `pack.bat` 打包

参数：`-Model DSLN|DCLN|GSLN|GCLN`（默认 DSLN）、`-Clean`、`-SkipPack`

## 五、烧录

### 5.1 关于 `.pac`：本 SDK 不产生它

- 全仓库对 `.pac` **零命中**。`.pac` 是**展锐 UNISOC** 的打包格式。
- 官方流程产出的是 **`.zip`**：`tools/scripts/pack.bat` 用
  `arelease -c tools\aboot -g -p ASR_CRANEL_EVB -v CRANEL_A0_08MB -i "cp=…,rd=…,rfbin=…,user_app=…"`
  把"基线分区包 + 你的 `user_app.bin`"合成一个 zip。
- 你下载的 **QFlash 是移远 Quectel 工具**（内部 `Setting\UpgradeDownload.ini` 指向
  UNISOC Download User Guide），它的 ASR 分支（`ASR\1\adownload1.exe`，自述
  "Asrmicro aboot download console application"）**认识** `download.json` / `arom-tiny` / `crane`，
  但全工具对 `ML307` / `CRANEL` / `ASR1606` **零命中**。
  → **能不能用 QFlash 烧本模组：未证实**。建议按下面顺序试。

### 5.2 推荐烧录路线（按优先级）

1. **官方 aboot 工具**（证据最强）
   从 SDK 来源仓库取 `aboot-tools-2022.03.01-win-x64.rar` 与 `ML307A-Windows驱动相关_V1.0.0.zip`
   （见 `docs/research/02-build-and-flash.md` 的来源清单），用其中的 aboot 下载器
   加载本工程产出的 `ML307A_DSLN_APP.zip`（内含 `download.json`）。
2. **QFlash 的 ASR 分支**：尝试加载同一个 zip。若报不支持型号，放弃该工具。
3. **向中移 FAE 确认**：直接问"ML307A-DSLN 量产下载工具与 .pac/zip 包格式"。

### 5.3 进入下载模式（你的底板没有 BOOT/RST 按键）

**首选软入口（免短接）**：
在 CDC 调试串口上发：
```
AT$MYDOWNLOAD=1
```
依据：该字符串在 ML307A-DSLN 底包 `cp.bin` 的内核 AT 命令表里**确实存在**
（取值域 `$MYDOWNLOAD: (0,1)`），且 QFlash 的 ASR 下载器在 `-a` 模式下正是发这条命令
让模组"fallback to download mode"。**实际行为需实测确认**。

**备选**：短接触点。⚠ 本工程**不提供**具体触点编号——官方 PDF 手册在本环境无法解析，
任何触点编号都会是臆造。请按此顺序排查：
1. 查 DEMO-ML307X-V1.04 原理图 / 丝印上的 `RES`、`BOOT`、`TP` 测试点
2. 社区经验（通用时序，仅参考）：拉低 BOOT/strap → 拉低 RESET → 释放 RESET → 释放 BOOT → 等待约 15s 出现下载端口
3. 下载模式 USB 设备名（据底包字符串）为 **`Arom Usb Boot Port`**

## 六、日志与调试串口

| 项目 | 值 | 证据 |
|---|---|---|
| 日志串口 | **UART0**，IOMUX `PIN_17/PIN_18`，FUNCTION1 | SDK 示例 `custom/applaction/main.c` + `drv_uart.c` |
| 波特率 | **921600** | 同上（`uart_open(CM_UART_DEV_0, 921600, u0_callback)`） |
| 开机标志 | `ML307A Start` | 同上 |

⚠ 注意：`cm_uart.h` 的波特率**枚举**里最大只有 256000，**没有 921600**。
SDK 示例走的是自带的 `drv_uart.c`（`baudrate` 参数是 `uint32_t`，支持 921600），
而 `cm_uart_open()` 收的是 `cm_uart_cfg_t`（枚举）。**不要混用**。
本工程日志走 `cm_log_printf()`（`cm_sys.h`），不需要应用自己配 UART；
若某底包上它不输出，切换方法见 `app/src/sdk_port.c` 顶部注释。

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| `process_begin: CreateProcess(NULL, echo ...) failed` | 缺少 shell，见"坑 1"，用 `SHELL=cmd.exe` |
| `couldn't create signal pipe, Win32 error 5` | MSYS sh 被安全策略限制，改用 `SHELL=cmd.exe` |
| `undefined reference to lwip_nwst_get_used_data` | 该符号**不在应用链接边界内**，属预期，见 `docs/02` 的边界表 |
| `fatal error: lwip_customer.h: No such file` | `lwip_api.h` 对应用层不自包含，**不要 include 它**，见 `docs/02` |
| `error: conflicting types for 'time_t'` | 同上，`lwip_api.h → ip_nat.h → dhcpd_api.h` 与 newlib 冲突 |
| 编译产物里找不到 `.pac` | 正常，官方只产 `.zip`，见 5.1 |
| `pack.bat` 报 `directory \out\images\ not exist` | 环境变量没给全，用 `tools/build_firmware.ps1` |

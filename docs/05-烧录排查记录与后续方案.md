## 一、设备实测事实（都是本机实测，非推测）

### 1.1 模组的 USB 形态与 PID 含义（由官方驱动 INF 反查确认）

官方驱动 `musbser.inf`（`aboot-tools-2022.03.01-win-x64\drivers\Drv\`）里的硬件 ID 列表是权威依据：

| PID | 含义 | 接口形态 | 观察到的时间点 |
|---|---|---|---|
| `VID_2ECC&PID_3012` | **正常固件模式** | MI_00 RNDIS + MI_02/03 AT + MI_04 DIAG | 最初插上时 |
| `VID_2ECC&PID_3010` | **中移最小系统（MiniSys，FOTA 用）** | MI_02 ComPort + MI_04 DIAG | 发 `AT$MYMINISYS=1` 之后 |
| `VID_2ECC&PID_3004` | **boot ROM 下载口**（INF 里标记为 `%DeviceDesc_download%`） | 专用下载设备 | **始终未出现** |

> 关键：`PID_3004` 才是 aboot 下载工具要等的设备。工具日志里的 `getting serial devices list...` + lwIP/IPv6 链路本地，说明它按 USB 设备枚举，而不是按 COM 口。

## 二、为什么必须整包烧录（不能只烧 user_app）

对 `prebuild/objs/ML307A/DSLN/cm_stub_DSLN.o` 反汇编，它是**硬编码绝对地址的跳转表**：

```asm
00000000 <osDelay>:      ldr pc, [pc, #1296]
00000004 <osThreadNew>:  ldr pc, [pc, #1296]
   ; 字面量池里全是固定内核地址：0x80397313 / 0x80397791 / 0x80045dfb ...
```

应用通过这个桩直接跳到内核的固定地址 → **应用与内核必须来自同一基线**。
而模组出厂是 `MTSH1S00`、我们按 `MBRH1S00` 编译 → 只烧 user_app 必然跳到错误地址。

⇒ 必须烧完整包（含内核），把 `MTS` 换成 `MBR`。这是官方 OpenCPU 开发的标准步骤。

## 三、进下载模式的尝试记录（全部失败）

| # | 方式 | 结果 |
|---|---|---|
| 1 | `AT$MYDOWNLOAD=1`（MBR 基线内核里的命令） | `ERROR` —— MTS 固件不支持（494 条受支持命令里没有它） |
| 2 | `AT+QDOWNLOAD=1`（移远命令） | `ERROR` |
| 3 | `AT*DOWNLOAD=1` / `AT+DOWNLOAD=1` / `AT$BOOT=1` / `AT$USB=1` / `AT*USB=1` | 全部 `ERROR` |
| 4 | `AT+MPRODUCTMODE` / `AT+MREBOOT` / `AT*MODEMRESET` | `ERROR` |
| 5 | `adownload1.exe -p COM3 -a -f`（AT 回落） | 死循环重发 AT 命令，无进展（211KB 刷屏日志） |
| 6 | `adownload1.exe -u -a`（普通模式） | 静默 0 输出 |
| 7 | `adownload1.exe -u -a`（最小系统模式） | 静默 0 输出 |
| 8 | `adownload1.exe -p COM3/COM4 -a`（115200 与 921600） | 静默 0 输出 |
| 9 | **短接 RES 到 GND**（运行中脉冲 + 上电时保持，共两次） | 模组确实复位了两次（COM 口消失再出现），但**回到最小系统模式**，未进下载模式 |
| 10 | 官方 GUI `aboot.exe`（AbootDownload 2022.03.01） | 卡在 `getting serial devices list...`，不列设备 |
| 11 | 官方 CLI `adownload.exe -p COM4/-u -a -s 115200` | 静默 0 输出 |

**已排除的原因**：
- 不是驱动缺失：装完 ASR 驱动后 `PID_3010&MI_02`/`MI_04` 与 `PID_3012` 各接口均 `Status=OK`；官方 `musbser.inf` 明确覆盖这些硬件 ID
- 不是波特率：115200 与 921600 都试过
- 不是包的问题：GUI 里包路径正确，日志显示 `initialized aboot release package successfully` / `download engine running in upgrade mode!`
- 不是工具版本：QFlash 的 `adownload1.exe` 与官方 `adownload.exe` 行为一致

**唯一没跨过的坎**：让模组从 `PID_3010`（最小系统）进入 `PID_3004`（boot ROM 下载口）。

## 四、后续方案（按优先级）

### 方案 A：彻底断电复位（先做这个，成本最低）

最小系统模式的标志 `$MYMINISYS=1` 在模式内部**无法用 `=0` 清掉**（返回 OK 但读回仍是 `1, 1`）。

- **把底板全部电源断开**（USB 线 + 独立电源都断），等 10 秒以上再上电
- 若模组恢复为 `PID_3012`（RNDIS + COM3 回来）→ 说明只是残留请求，模组完好
- 若仍是 `PID_3010` → 标志落在 NVM 里，需要方案 B/C

### 方案 B：硬件下载 strap（最可能的正解）

CSDN 同型号实操教程写的是「**拉低 RES 的引脚电平，进入到下载模式**」，但实测短接 RES 只复位、不进下载模式 → 说明该教程针对的是他自制的开发板（其 RES 测试点可能接了别的 strap）。

需要确认 **ML307A-DSLN 的下载/BOOT strap 引脚**。获取途径：
1. **《ML307A 硬件设计手册（OpenCPU 版）》** —— 在 Gitee `YZRDEG/ML307A/ML307A_OPENCPU手册/` 目录里（我这边无法解析 PDF）
2. **DEMO-ML307X-V1.04 原理图/丝印**：找 `BOOT` / `DL` / `BOOTCFG` / `TP` 之类的测试点（**不是 RES**）
3. **中移 FAE**（见第六节的问题清单）

### 方案 C：中移 MiniSys 的 FOTA 通道

最小系统模式里真正可用的下载命令是：

```
AT$MYFOTA=?   ->  $MYFOTA=<channel>,<mode>,<dst_ip/url:port>,<username>,<password>
AT$MYFOTA?    ->  $MYFOTA: 0
```

它需要一个 HTTP/FTP 目标。若 `<channel>` 支持本地通道，理论上可配合 QFlash 的 FOTA 组件（`FotaMimg.dll`）推送。**此路径未验证**，需要中移确认 `<channel>`/`<mode>` 的取值语义。

### 方案 D：换一个 SDK 基线匹配出厂固件

若能拿到与 `MTSH1S00` 匹配的 SDK 基线，理论上有机会只烧 user_app、不动 NVM/RF。但 SDK 1.4.2 只提供 `MBR`，未找到 MTS 来源 → 可行性低。

## 五、无论走哪条路，烧录时必须注意

1. **不要加 `-m / --production`**：那会让 `download.json` 里 `productionOnly: true` 的 `erase factory` 与 `fuse` 生效，可能抹掉产测数据/IMEI。普通 `upgrade` 模式会跳过它们。
2. **会擦除 `nvm`（1MB）并写入厂商通用 `rf.bin`** —— 这是整包烧录的既定行为（用户已确认）。
3. 写盘期间**不要拔线、不要断电**。
4. IMEI 已备份，必要时写回：`AT*MRD_IMEI=<IMEI>`。

## 六之二、后续补充实测（第二轮）

### 6.2.1 `ASR工具箱.exe` 的真实性质（已读源码确认）

仓库：<https://github.com/huwangkeji/asr-tools-pc>（PyInstaller 打包的 Python GUI）

- `serial_manager.py`：只是枚举串口
- `at_handler.py`：收发 AT 命令 + 一个 `reboot()`
- **没有任何烧录 / 下载模式 / aboot 相关代码**

结论：它是个**通用 AT 串口助手**，"能连上 COM4"只证明该串口可收发 AT（这一点用我自己的脚本同样能做），**不能用来烧录**。

### 6.2.2 最小系统模式无法用软件退出（多轮实测）

| 尝试 | 结果 |
|---|---|
| `AT$MYMINISYS=0` | 返回 `OK`，但 `AT$MYMINISYS?` **立刻读回仍是 `1, 1`** |
| `AT$MYMINISYS=0,0` / `=0,1` / `AT*NVMFLUSH` | `ERROR` |
| `AT$MYMINISYS=0` → `AT+CFUN=1,1`（干净序列，再复位） | 复位成功（OK），但模组**仍以 PID_3010 重新枚举**，RNDIS/COM3 都没回来 |
| `AT*USBT?` / `AT*PROD?` / `AT+MDUMPCFG?` / `AT*LWIPCTRL?` | 全部 `ERROR` |

⇒ **最小系统模式是一个"待完成 FOTA"的状态，在模式内部无法取消。**
最可能的解释：`fota_param` 分区里记录了"升级进行中"，引导程序因此每次都进最小系统等升级完成。
（注意 `download.json` 里正好有 `erase fota_param` / `erase fota_pkg` —— 整包烧录会把这两个分区擦掉，也就会清掉这个状态。）

### 6.2.3 最小系统里唯一的固件通道是 FOTA（网络升级）

```
AT+MFWCFG=?   ->  +MFWCFG: "url",        ← 可配置升级 URL
                  +MFWCFG: "auth",,      ← 可选鉴权
AT$MYFOTA=?   ->  $MYFOTA=<channel>,<mode>,<dst_ip/url:port>,<username>,<password>
AT$MYFOTA?    ->  $MYFOTA: 0
```

即：中移设计的最小系统是**通过网络（4G）从 URL 拉取固件做 FOTA**，不是本地 USB/串口烧录。
若要走这条路，需要：① 一个模组能访问到的公网 URL；② **中移 FOTA 专用包格式**（不是我们现在的 `ML307A_DSLN_APP.zip`）。
**此路径未验证**，且包格式不明，建议先向 FAE 确认。

### 6.2.4 从基线内核提取的完整私有命令表（有参考价值）

在 `ML307A-DSLN-MBRH1S00.axf` 中共提取到 **1761** 个 AT 命令注册项。与下载/模式相关的有：


## 六之三、★ 下载引脚已确认：`BOOT_MODE`（管脚 82，低电平有效）

来源：**《ML307A 硬件设计手册（OpenCPU 版）》**（中移官方，77 页，已下载到 `out/manuals/`）

### 官方原文（第 49 页 · 3.15.3 下载控制接口）

> 模组支持 USB 升级下载功能。**开机前将 BOOT_MODE 下拉至 GND，模组开机后将进入下载模式。**
> 在此模式下，模组可通过 USB 接口进行固件升级下载。
>
> Figure 19. BOOT_MODE 接口示意图：`BOOT_MODE —[1K]— 模组`，并带 TVS 与 Test point

### 引脚定义（第 45 页 · Table 35 CONTROL / 第 19 页 · Table 14）

| 引脚名 | 引脚号 | 类型 | 描述 | 电平门限 |
|---|---|---|---|---|
| PWR_ON/OFF | 7 | DI | 模组开关机 | 低电平有效（VIH 2.9~VBAT，VIL ≤0.5V） |
| RESET | 15 | DI | 模组复位 | 低电平有效（VIH 1.2/1.6/2.0V，VIL ≤0.5V） |
| **BOOT_MODE** | **82** | DI | **USB 强制下载** | **低电平有效（VIH 1.26/1.8/2.0V，VIL −0.3/0/0.54V）** |
| PWM0 / PWM1 / PWM2 | 74 / 75 / 21 | DO | PWM 输出 | 1.8V 域 |

### 两个关键提醒

1. **BOOT_MODE 与 `KEYOUT1`（键盘矩阵）复用**（第 44 页 3.14 KEYPAD）：
   > KEYOUT1 与 BOOT_MODE 引脚复用，**开机后才能做按键使用**
   ⇒ 底板上对应的丝印**可能是 `KEYOUT1`**，或走键盘接口排针，而不一定写 `BOOT_MODE`。

2. **必须是"开机前"就拉低**（第 52 页 3.18 测试点设计也再次确认）：
   > BOOT_MODE：用于控制模组进入**强制下载模式**，通过 USB 升级固件

### 正确操作时序

```
1) 底板彻底断电（USB + 独立电源都断）
2) 将 BOOT_MODE（管脚 82 / 板上可能标 KEYOUT1）短接到 GND，并保持
3) 在保持短接的状态下上电
4) 保持 1~2 秒后松开
   → 模组进入 USB 强制下载模式（设备会从 PID_3010 变为 PID_3004）
5) 电脑端用 aboot 工具加载 ML307A_DSLN_APP.zip 开始烧录
```

⚠ 注意：**RESET（管脚 15）只能复位，不是下载 strap** —— 这解释了为什么之前短接 RES 只看到复位、进不去下载模式。

# 09 · 短信远程配置 + 钉钉转发：实现规格

> 依据用户需求（2026-10-15）：用 13800000000 发短信「我要配置」→ 模组回**一条拼接短信**（模板 + 当前状态）；
> 之后用简化指令回填；短信自动转发到钉钉，支持**关键词**与**加签**；收发均支持**拼接短信**。

---

## 一、短信指令集（发件人白名单：仅 13800000000 可配置）

| 短信内容 | 作用 | 回执 |
|---|---|---|
| **我要配置** | 回一条拼接短信：模板 + 当前状态 | 见第二节 |
| `U <url>` | 设置 Webhook 地址（钉钉/企业微信等） | `OK U` / `ERR ...` |
| `T <secret>` | 设置加签密钥（`T -` 清空） | `OK T` |
| `K <keyword>` | 设置关键词（`K -` 清空） | `OK K` |
| `M <template>` | 设置内容模板 | `OK M` |
| `SAVE` | 落盘保存（cfg.bin） | `OK SAVED` |
| `STATUS` | 仅查状态 | 状态短信 |
| `RESET` | 重启模组 | 无（重启） |

- 回填**支持一条短信多行**（每行一条指令，逐行执行、逐行回执或合并回执一条）
- 非白名单号码发来的短信：**只转发，绝不执行配置**
- 所有指令解析在 `sms_svc` 内完成；配置读写经 `app_config` / `sdk_cfg_save`

---

## 二、「我要配置」回执内容（一条拼接短信）

```
ML307A 网关配置模板
U <Webhook地址>
T <加签密钥,无则 ->
K <关键词,无则 ->
M <模板,例 {from}|{time}|{text}>
SAVE保存 STATUS查询
--- 当前状态 ---
网络:已注册 CHINA MOBILE 信号31
NTP:已对时 2026-10-15 10:20:31
U:未设置 T:未设置 K:未设置
M:{from}|{time}|{text}
转发:全部(除黑名单) 收0/转0
```

模板占位符：`{from}` 发件号码、`{time}` 时间、`{text}` 正文、`{pdu}` 原始 PDU、`{idx}` 序号

---

## 三、拼接短信（Concatenated SM）规格

### 3.1 接收重组
- UDH 识别：`IEI=0x00`（16 位参考号：ref(2) + total + seq）、`IEI=0x08`（8 位参考号：ref(1) + total + seq）
- 缓存：按 `(发件号码, 参考号)` 建条目；保存各分片正文与序号
- 完成条件：收齐 `total` 片 → 按 seq 升序拼装 → 交给上层解析
- 超时：30 秒未收齐则丢弃该条目（避免占用内存）
- 容量：同时最多 4 个重组条目；单条拼接短信上限 8 片（≈ 500 UCS2 字 / 1200 ASCII 字符）

### 3.2 发送分包
| 编码 | 单片正文上限 | 说明 |
|---|---|---|
| UCS2（含非 ASCII） | **67 字** | 中文模板/回执走这条 |
| 7bit ASCII | **153 字符** | 纯 ASCII 时使用 |

- 每片 PDU 带 UDH：`05 00 03 <ref> <total> <seq>`（6 字节 UDH，含 UDHL）
- 参考号全局递增（0–255 循环）
- 逐片 `AT+CMGS=<len>` + PDU + `Ctrl-Z` 发送；每片等待 `+CMGS` 或 `OK`
- **SMSC 必须写入 PDU**（SDK 文档要求）：开机用 `AT+CSCA?` 读取并存缓存（形如 `+8613800738500,145`），失败则用 PDU 的 `00`（默认短信中心）

## 四、钉钉转发规格

### 4.1 关键词
- 若配置了 `K`，转发正文中**必须包含**该关键词（钉钉按正文匹配），实现上插到消息开头：`【<keyword>】<渲染后的模板>`

### 4.2 加签（HMAC-SHA256）
```
stringToSign = timestamp + "\n" + secret          // timestamp = 毫秒级
sign         = urlencode( base64( HMAC_SHA256(secret, stringToSign) ) )
最终 URL     = <配置的 url> + "&timestamp=" + timestamp + "&sign=" + sign
```
- 需要新增：**HMAC-SHA256**、**Base64**、**URL 编码**（`sha256.c` 已有 SHA-256，直接复用）
- 毫秒时间戳：`cm_rtc_get_current_time()` 秒 + 毫秒偏移（用 `osKernelGetTickCount` 补足）

### 4.3 NTP 对时（加签前提）
- 开机后（PDP 激活后）执行一次 NTP 对时：优先用 SDK/AT 的 NTP 通道，成功后 `cm_rtc_set_current_time()`
- 状态里回报对时结果；**若对时失败**：加签大概率被钉钉拒收 → 自动降级为"仅关键词"发送，并在状态短信中标注 `加签:已降级(时钟未同步)`

## 五、配置字段（`app_config_t` 新增，向后兼容）

| 字段 | 类型 | 默认值 |
|---|---|---|
| `webhook_url[192]` | char[] | `""`（未设置则不转发） |
| `webhook_secret[80]` | char[] | `""`（空=不签名） |
| `webhook_keyword[40]` | char[] | `""`（空=不加关键词） |
| `msg_template[160]` | char[] | `{from}\|{time}\|{text}` |
| `admin_num[24]` | char[] | `13800000000` |
| `concat_enable` | uint8 | 1（启用拼接短信收发） |
| `ntp_server[64]` | char[] | `ntp.aliyun.com` |

- 序列化格式**升版本**（`cfg_version+1`），旧配置自动按默认值补齐
- 主机测试需覆盖：新字段序列化往返、模板渲染、版本兼容

## 七、端到端验收步骤

1. 用 13800000000 发送「**我要配置**」→ 应收到一条（拼接）配置模板 + 状态短信
2. 回复：
   ```
   U https://oapi.dingtalk.com/robot/send?access_token=xxxx
   T SECxxxx
   K 报警
   M {from}|{time}|{text}
   SAVE
   ```
   → 应逐条/合并回执 `OK ...`
3. 用另一个号码给模组发一条短信 → 钉钉群应收到消息，内容含关键词 `报警`，且加签校验通过
4. `STATUS` 查询 → 状态短信显示已收/已转发计数、网络与对时状态
